# Decisions

## 2026-11-20 — FDOMAIN v1 Architecture & Tech Choices
- **DNS-as-code via GitHub + DNSControl → Cloudflare**: Chosen over manual Cloudflare edits (no history/dead-scan) and a stateful backend dashboard (unnecessary cost/maintenance for solo + trusted friends).
- **Single-domain root first (`domains/*.json`)**: Matches 1-domain scope without premature folder nesting; extensible later.
- **Trusted auto-merge + Admin CLI**: Admin pushes straight to `main` via `npm run sub`; `trusted[]` contributors get auto-merge via `pull_request_target` when only editing their own non-reserved files and checks pass; others require manual approval.
- **Always DNS-only (`proxied` omitted from user schema)**: Prevents ToS/abuse proxying through admin Cloudflare account, avoids breaking Vercel, and keeps CNAME targets inspectable by dead-subdomain scanner.
- **Support `_xxx` verification records via `extra`**: Allows GitHub Pages challenges, ACME DNS-01, and Netlify verification under owner's subdomain, plus `vercelVerify` under `_vercel.<root>`.
- **Unmanaged dashboard safety**: Apex (`@`) and admin dashboard records remain outside the repo via `IGNORE` + `drift-guard.ts` checking `dnscontrol preview` against managed labels before push.
- **Lookup UI with Next.js (`output: 'export'`) + Tailwind CSS**: Static output hosts at $0 on GitHub Pages or Vercel while keeping React/Next.js familiarity for future dashboard/auth upgrades without NestJS in v1.
## 2026-11-20 — FDOMAIN v2 Multi-Domain Fullstack & Instant Auto-DNS
- **Approach A (Fullstack Next.js on Vercel + Direct Provider APIs)**: Removed `output: 'export'` so Route Handlers execute live Name.com Core API (`core/v1`) and Cloudflare API mutations with HMAC-SHA256 `HttpOnly` cookie admin auth (`ADMIN_PASSWORD`, `SESSION_SECRET`), eliminating manual GitHub PR delays for the site owner while keeping PR workflows intact for external contributors.
- **Per-registrar driver strategy (`harrylee.dev` vs `vinamuse.store`)**: Checked authoritative NS (`1.1.1.1`): `harrylee.dev` uses Name.com DNS (direct `core/v1` API without static IP limits), whereas `vinamuse.store` uses Namecheap BasicDNS (Namecheap API requires static IPv4 whitelist + $50/20-domain eligibility and uses destructive full-zone `setHosts`). Configured `vinamuse.store` as `namecheap-manual` (1-click Copy helper + live DoH check) with seamless opt-in to `cloudflare-api` if nameservers move to Cloudflare.
- **No Web-UI-to-Git dual write**: Portal mutations write directly to Name.com / Cloudflare APIs (avoiding `GITHUB_TOKEN` on Vercel and avoiding noisy Vercel rebuilds per record); `deploy-dns.yml` runs DNSControl strictly for `cloudflare-gitops` zones.
- **Two-tier DNS safety & tiered visibility**: Anonymous callers receive only safe non-reserved `A`/`AAAA`/`CNAME` records (60s TTL cache); Admin unlocks full live view, creation, and deletion with hard blocks on apex `@`/`MX`/`NS`/`unmanaged` and explicit confirmation required for `reservedLabels`.
- **Retired GitHub Pages (`deploy-site.yml`)**: Standard Next.js Server/Route Handlers hosted cleanly on Vercel (`Root Directory = site` / `site/vercel.json`).
## 2026-11-20 — Warm Minimalist Editorial Bento Redesign & `next-intl` Upgrade (#4)
- **Warm Minimalist Editorial Bento + shadcn/ui + `@phosphor-icons/react`**: Replaced the chibi visual direction with an editorial warm-monochrome bento system (`#F7F6F3` / `#141413` Light/Dark via `<meta name="color-scheme">` + FOUC script), `Newsreader` + `Be Vietnam Pro` + `JetBrains Mono` fonts, duotone/bold Phosphor icons, faux-OS DNS preview chrome, and reusable shadcn/ui primitives (`Button`, `Card`, `Badge`, `Input`, Radix `DropdownMenu`) to match the developer DNS console context and scale cleanly.
- **Migrated from custom i18n helper to official `next-intl` (`NEXT_LOCALE` cookie mode)**: Adopted `createNextIntlPlugin('./src/i18n/request.ts')`, `site/messages/{vi,en}.json` (ICU plural/variable support), `NextIntlClientProvider`, Server Action `setUserLocale`, and Radix `DropdownMenu` language switcher while preserving clean non-prefixed URLs (`/`, `/claim`, `/directory`, `/health`) and `tests/i18n.test.ts` key/ICU-var parity checks.
## 2026-11-21 — Zero-Shift Layout Hardening, SSR Hydration & Lazy Loading (#5)
- **Server-hydrated initial Admin/Env/Capabilities state in `RootLayout`**: Passed `initialAdminState` (`authenticated`, `configured`, `envStatus`, `capabilities`) from `site/src/app/layout.tsx` directly into `AppShell` → `AdminSessionProvider`, eliminating client-mount waterfalls and post-hydration pop-in on `/health`, Sidebar Admin badge, and `/claim`.
- **Decoupled `/directory` sections with matched-geometry Skeletons**: Placed `Live Provider Records` in Section 1 inside a stable `min-h-[19rem]` container with 3 matched `h-[6rem]` Skeleton rows while loading, keeping Section 2 (`Tracked Subdomains`) independent so `#git-registry-heading` stays at `0px` vertical shift when `/api/dns/records` resolves.
- **On-demand `next/dynamic` lazy chunks with hover/focus preloading + App Router `loading.tsx`**: Code-split `AdminLoginDialog`, `DeleteRecordDialog`, and `GitOpsPrPanel` (`ssr: false`) out of initial page bundles with hover/focus prefetch, added matched Bento `loading.tsx` skeletons across all 4 routes, progressive `IntersectionObserver` pagination (`LIVE_PAGE_SIZE = 20`) on `/directory`, CSS `contain: layout style` (`.isolated-card`), and `content-visibility: auto; contain-intrinsic-block-size: auto 6rem` strictly on below-the-fold rows (`index >= 8`).
